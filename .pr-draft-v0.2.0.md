## Summary

v0.2.0 expands the transform catalogue from 4 (spatial-only) to 8 (four families):

- **spatial**    (existing)  `RandomHorizontalFlip`, `RandomVerticalFlip`, `Random90Rotate`, `RandomSpatialCrop`
- **spectral**   (new)       `GaussianBandNoise`, `RandomBandDropout`
- **photometric** (new)      `MultiplicativeIlluminationScaling`
- **mixing**     (new)       `Cutout`

All four new transforms are pure-torch, mask-aware, and HSI-canonical — drawn from Nalepa 2019, Ahmad 2024, Roddan 2024, and DeVries & Taylor 2017.

## API change (backwards-compatible)

`Transform.__call__` and `AugmentationCompose` now accept an optional `wavelengths: list[float] | None = None` argument. v0.2.0 transforms ignore it; future wavelength-aware transforms (v0.3.0+) will consume per-band centre wavelengths in nanometres.

External `Transform` subclasses must add `wavelengths` to their signature — see CHANGELOG.md for the migration note. The bundled transforms and `tests/fixtures/fake_transform.py` are the reference pattern.

## Module reorg

Transforms are now split by family on disk: `spatial.py`, `spectral.py`, `photometric.py`, `mixing.py`. No public symbol moves — everything still resolves through `TRANSFORM_REGISTRY` by name.

## Tutorial notebook

`notebooks/use_cases/lentils_augmentation.ipynb` gains three new sections (§8–§11) — one per new family — with the same 3-band visualisation pattern as the existing spatial sections. The §12 full-compose demo now exercises all seven concrete v0.2.0 transforms across four families. Re-executed end-to-end on the 334×334×61 lentils cube; 0 errors.
